SOURCES

Every outside source this project used, cited in MLA style (9th edition). Each one has a short source record under it: who made it, what evidence it gives, how current it is, why it was made, and how the project used it.

Every link was opened again on 7 November 2026. One source that no longer loads is listed at the end of the works cited.

HOW THE SOURCES WERE JUDGED

Each source got the same five questions, from the source record in the capstone process notebook:

  1. Who made it? A person, a company or an official body, and whether they know the subject first-hand.
  2. What evidence does it give? Measurements, the real thing (such as the game itself), or someone’s opinion.
  3. How current is it? When it was written or last updated, and whether that matters for this use.
  4. What is its purpose, and could it be biased? Selling something, reviewing, teaching or setting a standard.
  5. How does it connect to the question? What the project took from it, and what it was not trusted for.

Each source is also marked PRIMARY or SECONDARY. A primary source is the original thing or first-hand evidence: the 1992 game itself, its program code, the official court rules. A secondary source describes or reviews something at second hand, such as a magazine review or an encyclopedia article.

The rule the project followed: facts about how the arcade game works come from primary sources (the game run in an emulator, and its decompiled code). Reviews and databases were used for background and for what players thought, never as proof of a rule or a number.

CHECKING THE COURT AGAINST THE WORLD STANDARD

The game’s court is measured in its own units, not metres. To check it, each line was turned back into metres and compared with the World Squash Federation’s official singles court.

What this shows. Every size and height matches the official court to the centimetre, except two small differences:

  • The service line is 1 cm high. One game unit of height is about 2.8 cm, so 63 units is the nearest the game can get. The line is only drawn; no rule uses it.
  • The game’s lines have no thickness, and the ball’s centre is tested against them. On a real court the ball is out if any part of it touches the 50 mm line. The 1992 arcade’s own tin and out checks weren’t found in its code, so these rules are the project’s design, not a copy.

The game’s line heights were first taken from “World Squash” numbers in October without a source being written down. This check, against the official document, fixes that gap. Professional events may lower the tin to 0.43 m; the game uses the standard 0.48 m.

HOW AI WORK WAS CHECKED

The AI tools wrote the code, made the art and sounds, and helped with research. None of that was trusted just because the AI said it was right. It was checked four ways:

  1. Tests against the 1992 game. Two recorded runs of the original game, played in MAME, are replayed against the new code frame by frame. Ball positions match exactly in 12,309 of 12,390 frames and 17,452 of 17,563 frames (99.3%), every one of the 458 ball flights (164 + 294) is explained, and all 244 shot choices are the same. The tests run after every change, and a change that makes them worse fails (a regression test).
  2. Play-tests by Ronin. At each checkpoint (CP-B to CP-G), Ronin played the game and wrote down what felt wrong. Those notes caused whole fix-up sessions, such as the drop-shot fix and the reshaped difficulty levels. They are in the build log.
  3. Measuring, not guessing. A script plays 1,000 rallies at each CPU level and counts who wins, so a claim like “level 5 is harder than level 4” is backed by numbers. The charts are on Findings.
  4. Owner review. Every design choice (rules, colours, art, sounds, difficulty) was approved or changed by Ronin and written down with the date and the reason in the project’s decision log.

Facts from research were treated the same way: each was marked confirmed once it was seen in the running game, or unconfirmed until then. On this page, every link was re-opened and the court numbers were checked against the official specification.

Limits. The AI also wrote the tests, so a test could share the code’s mistake; the recorded runs come from one version of the arcade game and a bot player; and almost all the play-testing was one person. More on Findings → Limitations.

GLOSSARY

The technical words used on this site, in plain words first. Other pages link here with /sources/#g-<term>.

Checkpoint
A planned stop in the build where Ronin play-tests the game and decides what to change before more is built. This project had checkpoints CP-A to CP-G.
Coefficient of restitution
How bouncy a hit is: the speed after a bounce divided by the speed before. 1 would lose no speed; 0 would stop dead. In the 1992 game it changes with how hard the ball hits, from 0.68 for slow balls down to 0.31 for fast ones.
Commit
One saved change in version control, with a message saying what changed and why. The build log is made from the project’s commits.
Decompile
To turn a program’s machine code (the numbers a processor runs) back into code a person can read. The result is a best guess with no original names or comments. Done here with Ghidra.
Deployment
Putting a new version of the game or site on the internet so anyone can use it. Here, pushing to GitHub deploys to Cloudflare.
Determinism
Giving exactly the same result every time from the same start. The game’s physics is deterministic, so a test or a replay always comes out the same on every computer.
Difficulty curve
How much harder a game gets from one level to the next. Hogg Squash has CPU levels 1 to 9, measured by how often a beginner wins at each.
Emulator
A program that copies old hardware in software, so a game made for it runs on a modern computer exactly as it did. MAME is an arcade emulator.
Fixed-point
Doing maths with whole numbers that stand for fractions, instead of decimals. The 1992 arcade did this, and so does the new game, so both give identical answers.
Frame rate
How many pictures (frames) a game shows each second. The arcade ran at about 57.4 frames a second, and the new game’s physics steps at the same rate.
Generative AI
AI that makes new text, code, pictures or sound from a written request (a prompt). Claude, SpriteCook and ElevenLabs are generative AI.
Golden test
A test that compares the program’s output with a recording known to be right (the “golden” copy). Here, the recording is the 1992 game’s ball, frame by frame.
Iteration
Building something in rounds: make it, test it, change it, repeat. Each round is an iteration.
MLA style
The Modern Language Association’s rules for citing sources. This page uses the 9th edition.
Palette
The fixed set of colours used for the art. Hogg Squash’s palette has 36 colours, including Hogg red.
Play-test
Playing a game to find problems and judge how it feels, then writing down what to change.
Primary source
The original thing or first-hand evidence: the game itself, its code, an official rulebook.
Regression test
A test run after every change to make sure nothing that used to work has broken (“regressed”).
Reverse engineering
Working out how something was made by studying the finished thing: here, running the 1992 game in an emulator and decompiling its code to learn its rules.
ROM
Read-only memory: the chips that hold an arcade game’s program, graphics and sounds. A copy of them is also called a ROM. The project used one for reference only; nothing from it is in the game.
Secondary source
A source that describes, reviews or explains something at second hand, such as a review or an encyclopedia article.
Short line
The line across the floor that marks the front of the service boxes, a little over halfway back from the front wall.
Sprite
A small picture that moves around the screen, like a player or the ball. An animation is a set of sprites shown one after another.
Superellipse
A shape between an oval and a rectangle: a rectangle with rounded corners, where one number sets how square it is. The area a player can reach is a superellipse; Ronin picked the squareness by playing several.
Tin
The strip along the bottom of the front wall, like a net in tennis. A ball that hits it is out. Its top is 0.48 m high.
Version control
A system that saves every change to the code with a date and a message, so any old version can be brought back. This project uses Git and GitHub.
